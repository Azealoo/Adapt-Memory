## Relationship Summary (Research Context)

```
USERS (Research Personas) (1) ──→ (N) USER_PREFERENCES
    │
    ├── (1) ──→ (N) USER_INTERACTIONS
    │
    └── (1) ──→ (N) TASK_HISTORY

USER_PREFERENCES (1) ──→ (N) USER_INTERACTIONS

PREFERENCE_TEMPLATES (standalone table)
```

## Key Relationships (Research Context)

1. **Research Personas → User Preferences**: One persona can have many preferences
2. **Research Personas → User Interactions**: One persona can have many interactions  
3. **Research Personas → Task History**: One persona can have many task completions
4. **User Preferences → User Interactions**: One preference can be referenced by many interactions
5. **Preference Templates**: Standalone table for reusable templates

## Data Flow (Research Context)

```
Persona-Robot Interaction → Persona Response → Preference Learning → Database Storage
     ↓
Task Completion → Performance Metrics → Database Storage
     ↓
Research Analytics & Reporting → Preference Learning Insights
```

## Index Strategy

- **Primary Keys**: All tables have auto-incrementing primary keys
- **Foreign Keys**: Indexed for join performance
- **Search Fields**: persona_id, preference_type, interaction_type
- **Time-based**: created_at fields for temporal queries
- **Boolean Fields**: is_active for filtering active records

## Common Query Patterns

1. **Get user preferences**: `SELECT * FROM user_preferences WHERE user_id = ? AND is_active = TRUE`
2. **Get interaction history**: `SELECT * FROM user_interactions WHERE user_id = ? ORDER BY created_at DESC`
3. **Get task statistics**: `SELECT COUNT(*), AVG(completion_time) FROM task_history WHERE user_id = ?`
4. **Get preference templates**: `SELECT * FROM preference_templates WHERE preference_type = ? AND is_active = TRUE`
